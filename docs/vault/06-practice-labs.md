## 🧪 Лаба 1. Vault с нуля

### Что делаем
Поднимаем Vault «по-взрослому» (не dev), учимся распечатывать и работать с KV.

### Требования
- [ ] Vault с файловым или Raft-хранилищем, TLS можно самоподписанный
- [ ] Выполнен `operator init`, ключи и root-токен сохранены (для учёбы — надёжно записаны)
- [ ] Перезапуск → Vault запечатан → распечатан вручную
- [ ] Включён аудит в файл, проверена запись о чтении секрета
- [ ] Включён KV v2, создана структура `secret/{dev,stage,prod}/<сервис>/<назначение>`
- [ ] Отработаны `put`, `patch`, `get -field`, `list`, версии, `undelete`, `destroy`
- [ ] Ограничено число версий
- [ ] Сделан снапшот и восстановление (для Raft)

### Проверка
```bash
vault status                      # Sealed: false, Storage Type: raft/file
vault kv get -field=password secret/prod/billing/db
vault kv metadata get secret/prod/billing/db
grep -c '"type":"request"' /vault/logs/audit.log
```

## 🧪 Лаба 2. ⭐ Политики и auth methods

### Что делаем
Выдаём доступ человеку, приложению и CI — каждому свой способ и свои права.

### Требования
- [ ] Политика `app-billing`: чтение только `secret/data/prod/billing/*`
- [ ] Политика `devops`: управление `secret/*`, но `deny` на финансовый раздел
- [ ] Пользователь через `userpass` (или OIDC, если есть) с политикой `devops`
- [ ] AppRole `billing`: короткий `secret_id_ttl`, `num_uses=1`, `token_ttl=1h`
- [ ] Проверено: приложение читает свой путь, чужой — `permission denied`
- [ ] SecretID выдан через response wrapping, повторный `unwrap` не проходит
- [ ] Токены отозваны по префиксу метода
- [ ] Политики лежат в git как файлы `.hcl`

### Проверка
```bash
VAULT_TOKEN=$APP_TOKEN vault kv get secret/prod/billing/db      # ok
VAULT_TOKEN=$APP_TOKEN vault kv get secret/prod/finance/db      # permission denied
vault token revoke -prefix auth/approle/
```

### Вопросы себе
- Что увидит злоумышленник, укравший RoleID (без SecretID)?
- Как быстро я смогу отозвать доступ конкретного сервиса?

## 🧪 Лаба 3. Динамические креды для PostgreSQL

### Что делаем
Самая показательная возможность Vault: временные учётные записи в базе.

### Требования
- [ ] PostgreSQL поднят (можно из блока «Базы данных»)
- [ ] Создана отдельная админ-учётка `vault_admin` (не суперпользователь базы без нужды)
- [ ] Включён движок `database`, настроено подключение
- [ ] Роль `billing-ro` с `default_ttl=5m`, `max_ttl=1h`
- [ ] Получены креды, выполнено подключение к базе этими кредами
- [ ] Дождался истечения TTL — пользователь исчез из `\du`
- [ ] Проверены `lease renew` и `lease revoke`
- [ ] Выполнен массовый отзыв по префиксу
- [ ] Посчитано, сколько ролей создаётся при частых запросах, сделан вывод про `max_connections`

### Проверка
```bash
vault read database/creds/billing-ro
psql "postgresql://<vault_user>:<vault_pass>@localhost:5432/shop" -c 'select 1'
sudo -u postgres psql -c '\du' | grep v-        # временные роли
vault lease revoke -prefix database/creds/
```

### Вопросы себе
- Что произойдёт с приложением, если лиз истечёт во время работы?
- Как я объясню команде разницу «ротация пароля раз в год» и «учётка живёт час»?

## 🧪 Лаба 4. Vault + Kubernetes + CI

### Что делаем
Замыкаем контур: секреты доезжают до подов и до пайплайна без ручного копирования.

### Часть A. Kubernetes
- [ ] Vault установлен в kind (Helm) или доступен снаружи
- [ ] Включён и настроен `kubernetes` auth method
- [ ] Роль привязана к конкретному ServiceAccount и namespace
- [ ] Вариант 1: Agent Injector — секрет появляется файлом в поде
- [ ] Вариант 2: External Secrets Operator — секрет появляется как k8s Secret
- [ ] Проверено: под из другого namespace доступ не получает

### Часть B. CI
- [ ] Настроена `jwt`-роль с `bound_claims` по проекту и ветке
- [ ] Пайплайн получает токен, читает секрет, отзывает токен в `after_script`
- [ ] Проверено: пайплайн из другой ветки доступ не получает
- [ ] В переменных CI нет ни одного статического секрета Vault

### Проверка
```bash
kubectl exec -n billing deploy/billing -- cat /vault/secrets/db
kubectl get secret -n billing billing-db -o jsonpath='{.data.password}' | base64 -d
# в CI: echo $VAULT_TOKEN | head -c 8   (только префикс, не весь токен!)
```
