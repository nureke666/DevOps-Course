# System Design: бэкенд + DevOps

Курс по проектированию систем с двух сторон. Сначала — **как это устроено**: требования, API,
модель данных, кеш, шардирование. Потом — **как это развернуть и держать в проде**: выкатка,
автоскейлинг, SLO и алерты, отказы, бэкапы и DR, безопасность, стоимость.

> **Для кого:** бэкенд-разработчикам, которым нужно думать об эксплуатации, и DevOps/SRE,
> которым нужно понимать данные и API. Подходит и для подготовки к собесу, и для работы:
> design doc пишется по тем же шагам, что и ответ на интервью.

---

## Как устроен курс

- **Блоки 1–4 — теория.** Метод, строительные блоки, данные, надёжность. Темы, которые уже
  подробно разобраны на сайте (CAP, репликация, Kafka, SLO), здесь не повторяются — на них
  стоят ссылки.
- **Блоки 5–6 — разборы задач.** Каждая задача решается по одной схеме:

```text:no-line-numbers
 требования → оценки → API → модель данных → схема → глубже: 2–3 ключевых решения
      → узкие места и рост ×10 → ⚙️ эксплуатация → trade-offs → что спросят дальше
```

- **⚙️ Эксплуатация** — обязательный раздел каждой задачи, всегда из 7 вопросов: развёртывание,
  масштабирование, наблюдаемость, отказы, данные и DR, безопасность, стоимость. Откуда он
  взялся и как на него отвечать — в
  [04. Бэкенд-собес и DevOps-собес](/system-design/basics/04-backend-vs-devops).
- **Блок 7 — практика.** Лабы на linkd из [пет-проекта](/project/) и пробные интервью.
- **Сквозной пример — linkd.** Тот же сервис коротких ссылок, что в пет-проекте: на нём
  удобно показать, что меняется при росте в 10, 100 и 1000 раз.

Каждая тема заканчивается задачами: теория, «что тут не так», практика, инциденты и вопросы
с собеседований с ответами.
