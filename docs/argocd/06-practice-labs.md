## 🧪 Лаба 1. Установка и первое приложение

### Что делаем
Ставим ArgoCD, подключаем свой репозиторий, деплоим приложение.

### Требования
- [ ] kind/minikube-кластер поднят
- [ ] ArgoCD установлен, пароль изменён, вход через CLI работает
- [ ] Создан git-репозиторий со структурой `manifests/demo/`
- [ ] Репозиторий подключён (публичный — по HTTPS, приватный — по SSH-ключу)
- [ ] `Application` создан **декларативно** (YAML в git, не кликами)
- [ ] Приложение синхронизировано, статус `Synced` + `Healthy`
- [ ] Разобрано дерево ресурсов в UI
- [ ] Проверен `argocd app get`, `argocd app diff`, `argocd app logs`

### Проверка
```bash
argocd app list
kubectl get all -n demo
argocd app get demo | head -20
```

### Вопросы себе
- Что произойдёт, если я изменю манифест в git и ничего не нажму?
- Где в UI видно, чем кластер отличается от git?

## 🧪 Лаба 2. ⭐ Self-heal, prune и откаты

### Что делаем
Отрабатываем поведение, ради которого и внедряют GitOps.

### Сценарии
```text:no-line-numbers
1. auto-sync выключен  → меняем git → приложение OutOfSync → синхронизируем вручную
2. auto-sync включён   → меняем git → применяется само (замерь время)
3. selfHeal выключен   → kubectl scale → OutOfSync навсегда
4. selfHeal включён    → kubectl scale → возвращается за секунды ⭐
5. prune выключен      → удалили Service из git → он остался в кластере
6. prune включён       → удалили Service из git → удалён из кластера
7. сломанный образ     → Synced + Degraded → разбор через describe/logs
8. откат rollback      → состояние вернулось, но git «сломан»
9. откат git revert    → ⭐ правильный откат, git и кластер согласованы
```

### Требования
- [ ] Все девять сценариев отработаны и записаны (что увидел, сколько заняло)
- [ ] Добавлен HPA и решена проблема вечного `OutOfSync` через `ignoreDifferences`
- [ ] Добавлен `PreSync`-hook (Job) и проверено поведение при его падении
- [ ] Проверено поведение с `finalizer` и без него при удалении Application
- [ ] Настроены уведомления или алерт на `Degraded`

### Вопросы себе
- Как объяснить коллеге, почему его правка в кластере «исчезла»?
- Какой порядок действий при инциденте: откат через Argo или через git?

## 🧪 Лаба 3. App of Apps и бутстрап кластера

### Что делаем
Собираем кластер «из одного манифеста».

### Структура
```text:no-line-numbers
gitops-repo/
├── bootstrap/root-app.yaml
├── apps/
│   ├── platform-ingress.yaml      sync-wave: -2
│   ├── platform-monitoring.yaml   sync-wave: -1
│   ├── demo.yaml
│   └── podinfo.yaml
├── manifests/demo/
└── projects/team-a.yaml
```

### Требования
- [ ] Корневой Application применяется одной командой
- [ ] Дочерние приложения создаются автоматически
- [ ] Платформенные компоненты имеют меньший `sync-wave`
- [ ] Создан `AppProject` с ограничениями и хотя бы одно приложение в нём
- [ ] Добавление нового сервиса = коммит одного файла
- [ ] ⭐ Полный тест: удалить кластер, создать новый, применить один манифест
- [ ] Замерено время полного разворачивания
- [ ] (со звёздочкой) То же самое переписано на ApplicationSet с `git.directories`

### Проверка
```bash
kind delete cluster --name gitops && kind create cluster --name gitops
# установка argocd + kubectl apply -f bootstrap/root-app.yaml
watch argocd app list
```

### Вопросы себе
- Что не восстановилось автоматически и почему?
- Что произойдёт, если удалить файл из `apps/` при включённом `prune`?

## 🧪 Лаба 4. Helm-чарты и секреты

### Что делаем
Деплоим сторонний и свой чарт, разносим окружения и решаем вопрос секретов.

### Требования
- [ ] Публичный чарт (например, `podinfo`) задеплоен с зафиксированной версией
- [ ] Свой минимальный чарт в конфиг-репозитории, два окружения через values-файлы
- [ ] Проверено: `helm list -A` не показывает приложения Argo
- [ ] Тег образа обновляется отдельным коммитом (имитация CI)
- [ ] Сделан Kustomize-вариант (base + overlays) для сравнения
- [ ] ⭐ Установлен контроллер Sealed Secrets (через Argo), секрет запечатан
      и лежит в git
- [ ] Приложение использует этот секрет и работает
- [ ] (со звёздочкой) Вместо Sealed Secrets настроен External Secrets + Vault
- [ ] В CI конфиг-репозитория добавлена проверка на секреты (`gitleaks`)

### Проверка
```bash
kubectl get sealedsecret,secret -n demo
argocd app get podinfo | grep -E 'Health|Sync'
git log --oneline -- manifests/ | head
```

### Вопросы себе
- Где хранится ключ, которым расшифровываются секреты, и что будет при его потере?
- Как я восстановлю секреты при полном пересоздании кластера?

## 🏁 Что должно остаться после блока

```text:no-line-numbers

├── bootstrap/root-app.yaml          # кластер разворачивается одной командой
├── projects/                        # AppProject по командам
├── apps/                            # Application или ApplicationSet
├── manifests/                       # Kustomize base + overlays
├── charts/                          # свои чарты и values по окружениям
├── secrets/                         # SealedSecret / ExternalSecret
├── .gitlab-ci.yml                   # проверки манифестов и секретов
└── README.md                        # как развернуть с нуля, правила работы
```

Плюс личные заметки: что делает `selfHeal`, как выглядит `Degraded`, как откатывались,
сколько заняло восстановление кластера. Это и есть содержание ответа на собеседовании.
