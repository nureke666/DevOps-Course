# 02. Command Line: жизнь в терминале

> Источник: `02_command_line.txt` (Grasshopper, 19 уроков)
> **После темы ты умеешь:** свободно ходить по файловой системе, создавать/копировать/удалять файлы,
> искать что угодно через `find`, читать `man` и не бояться чёрного экрана.

## 🗺️ Схема: что происходит, когда ты жмёшь Enter

```text:no-line-numbers
  Ты печатаешь: ls -l /etc
        │
        ▼
┌───────────────────┐
│  SHELL (bash)     │  1. разбирает строку на слова
│                   │  2. раскрывает * ? ~ $VAR  (globbing/expansion)
│                   │  3. ищет команду: alias → функция → builtin → $PATH
└─────────┬─────────┘
          │ fork() + exec()
          ▼
┌───────────────────┐        ┌──────────────────────────┐
│  ПРОЦЕСС /bin/ls  │───────▶│ KERNEL: syscall openat() │
│                   │◀───────│         getdents()       │
└─────────┬─────────┘        └──────────────────────────┘
          │ пишет в stdout (fd 1)
          ▼
     ТВОЙ ЭКРАН              (а exit code уходит обратно в shell → $?)
```

**Терминал** — окно/устройство ввода-вывода. **Shell** — программа внутри него, которая понимает команды.
Их часто путают: терминал — это «телевизор», shell — «то, что в нём показывают».

## 1. The Shell — оболочка

```bash
echo $SHELL     # /bin/bash   — какой shell назначен твоему пользователю
echo $0         # -bash       — какой shell выполняется прямо сейчас
cat /etc/shells # список установленных оболочек
```

| Shell | Комментарий |
|-------|-------------|
| `sh` | POSIX-минимум. В Ubuntu это `dash` — быстрый, но без «вкусностей» bash |
| `bash` | Bourne Again Shell — стандарт де-факто на серверах Linux |
| `zsh` | Дефолт в macOS, много удобств, oh-my-zsh. Для личного ноута |
| `fish` | Самый дружелюбный, но **не POSIX-совместим** — скрипты не переносятся |

⚠️ **Важно для DevOps:** скрипты в проде пиши с `#!/usr/bin/env bash` и проверяй, что он реально bash.
Если написать `#!/bin/sh`, то на Ubuntu это `dash`, и конструкции `[[ ]]`, массивы, `source` — сломаются.

### Анатомия приглашения (prompt)

```text:no-line-numbers
vagrant@learn-linux:~$
   │         │        │ │
   │         │        │ └── $ = обычный пользователь,  # = root
   │         │        └──── текущая директория (~ = домашняя)
   │         └───────────── hostname
   └─────────────────────── имя пользователя
```

Это задаётся переменной `PS1`. Знать полезно: на скриншотах и в логах по `#` сразу видно, что работали под root.

### Анатомия команды

```bash
ls   -l  --human-readable   /var/log
│     │          │              │
│     │          │              └── аргумент (на чём работаем)
│     │          └── длинная опция (два дефиса, читаемое имя)
│     └── короткая опция (один дефис, можно склеивать: -lh == -l -h)
└── команда
```

Типы команд (порядок поиска шеллом важен!):

```bash
type -a ls      # ls is aliased to `ls --color=auto' / ls is /usr/bin/ls
type cd         # cd is a shell builtin      ← встроена в bash, файла нет
which python3   # /usr/bin/python3           ← путь к исполняемому файлу
command -v jq   # POSIX-способ проверить наличие команды (лучше в скриптах)
```

Поиск идёт так: **alias → функция → builtin → файл в `$PATH`**.

```bash
echo $PATH
# /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
#  ↑ ищется слева направо, первый найденный выигрывает
```

## 2. pwd — где я нахожусь

```bash
pwd             # /home/vagrant
pwd -P          # физический путь, symlink'и раскрыты
```

**Абсолютный путь** начинается с `/` — от корня: `/var/log/nginx/access.log`.
**Относительный** — от текущей директории: `nginx/access.log`, `../etc`.

```text:no-line-numbers
/                       ← корень, начало всего
├── home/
│   └── vagrant/        ← твой дом, он же ~
│       └── projects/
├── etc/                ← конфиги
├── var/
│   └── log/            ← логи
└── usr/
    └── bin/            ← программы
```

Спецсимволы путей:

| Символ | Значение |
|--------|----------|
| `.` | текущая директория |
| `..` | родительская |
| `~` | домашняя директория текущего юзера (`/home/vagrant`) |
| `~user` | домашняя директория юзера `user` |
| `-` | предыдущая директория (для `cd`) |
| `/` | корень |

## 3. cd — перемещение

```bash
cd /var/log      # абсолютный
cd nginx         # относительный (из /var/log → /var/log/nginx)
cd ..            # на уровень вверх
cd ../..         # на два уровня
cd               # домой (то же, что cd ~)
cd -             # вернуться в ПРЕДЫДУЩУЮ директорию ← очень экономит время
cd /             # в корень
```

💡 Фишки, которые надо довести до автоматизма:
- **TAB** — автодополнение. Жми постоянно. Двойной TAB — показать варианты.
- `cd -` — прыгать между двумя каталогами (например, между конфигом и логом).
- `pushd /var/log` / `popd` — стек каталогов, когда нужно «сходить и вернуться».

⚠️ Пробелы в именах ломают команды: `cd my folder` → ошибка.
Правильно: `cd "my folder"` или `cd my\ folder`. В DevOps **не создавай файлы с пробелами** — просто не создавай.

## 4. ls — просмотр содержимого

```bash
ls                 # просто имена
ls -l              # длинный формат: права, владелец, размер, дата ← ГЛАВНЫЙ РЕЖИМ
ls -a              # включая скрытые (начинаются с точки)
ls -h              # человекочитаемые размеры (K, M, G) — только с -l
ls -t              # сортировка по времени изменения (новые сверху)
ls -r              # обратный порядок
ls -S              # сортировка по размеру
ls -R              # рекурсивно
ls -d */           # только директории
ls -i              # показать inode
ls -1              # по одному в строке (удобно для пайпа)

# Рабочие комбинации:
ls -lh             # самая частая
ls -lah            # + скрытые
ls -lrt            # ПО ВРЕМЕНИ, новые ВНИЗУ — идеально для /var/log
ls -lhS            # что занимает больше всего места
```

### Читаем вывод `ls -l` — это надо понимать построчно

```text:no-line-numbers
-rw-r--r--  1 root root  1.2K Jan 15 10:30 nginx.conf
drwxr-xr-x  3 www  www   4.0K Jan 15 10:30 sites-enabled
lrwxrwxrwx  1 root root    21 Jan 15 10:30 link -> /etc/nginx/nginx.conf
│└┬┘└┬┘└┬┘  │  │    │      │        │            │
│ │  │  │   │  │    │      │        │            └─ имя (для symlink: -> цель)
│ │  │  │   │  │    │      │        └─ дата/время изменения
│ │  │  │   │  │    │      └─ размер в байтах (с -h: K/M/G)
│ │  │  │   │  │    └─ группа-владелец
│ │  │  │   │  └─ пользователь-владелец
│ │  │  │   └─ число жёстких ссылок (для каталогов = число подкаталогов + 2)
│ │  │  └─ права для ОСТАЛЬНЫХ (other)
│ │  └─ права для ГРУППЫ (group)
│ └─ права для ВЛАДЕЛЬЦА (user)
└─ тип: - файл, d каталог, l симлинк, c/b устройство, s сокет, p pipe
```

Подробно про права — в теме [06_permissions.md](/linux/06-permissions).

## 5. touch — создать файл / обновить время

```bash
touch newfile.txt              # создать пустой файл (или обновить mtime существующего)
touch a.txt b.txt c.txt        # сразу несколько
touch file{1..5}.txt           # brace expansion → file1.txt … file5.txt
touch -d "2020-01-01" old.txt  # задать конкретную дату
touch -t 202001011200 old.txt  # формат YYYYMMDDhhmm
```

У файла три времени:

| Время | Что значит | Как посмотреть |
|-------|-----------|----------------|
| **atime** | последний доступ (чтение) | `ls -lu` |
| **mtime** | последнее изменение **содержимого** | `ls -l` (по умолчанию) |
| **ctime** | последнее изменение **метаданных** (права, владелец) + содержимого | `ls -lc` |

```bash
stat file.txt    # покажет все три + inode + размер + права
```

💡 В DevOps `touch` часто используют как **флаг-файл**: `touch /var/run/deploy.lock` — «идёт деплой,
не лезь». И для проверки прав на запись в каталог.

## 6. file — что это за файл на самом деле

В Linux **расширение ничего не значит**. Тип определяется по содержимому («магическим байтам»).

```bash
file /etc/passwd      # ASCII text
file /bin/ls          # ELF 64-bit LSB pie executable, x86-64, dynamically linked
file /etc             # directory
file archive.tar.gz   # gzip compressed data
file script.sh        # Bourne-Again shell script, ASCII text executable
file /dev/sda         # block special
file image.png        # PNG image data, 1920 x 1080
```

⚠️ Реальный кейс: скачал «zip», а внутри — HTML-страница с ошибкой. `file` сразу это покажет,
а `unzip` будет ругаться непонятно.
Второй кейс: `file script.sh` показывает `with CRLF line terminators` — это виндовые переносы строк,
из-за них скрипт падает с `bad interpreter: /bin/bash^M`. Лечится `dos2unix`.

## 7. cat — вывести файл

```bash
cat file.txt                # показать
cat -n file.txt             # с номерами строк
cat -b file.txt             # номера только непустым строкам
cat -A file.txt             # показать спецсимволы: $ конец строки, ^I таб ← ловит битые конфиги
cat file1.txt file2.txt     # склеить несколько (conCATenate — отсюда имя)
cat f1 f2 > all.txt         # склеить в новый файл
tac file.txt                # то же, но в обратном порядке строк
```

Heredoc — создать файл без редактора (важнейший приём для скриптов и Dockerfile):

```bash
cat > /tmp/app.conf <<'EOF'
listen = 8080
debug  = false
EOF
```
`<<'EOF'` (в кавычках) — текст вставляется **как есть**. Без кавычек `$VAR` внутри подставится.

⚠️ **Не делай `cat` на больших файлах** (`cat /var/log/syslog` на 2 ГБ) — забьёшь терминал и съешь
CPU. Для больших файлов — `less`, `head`, `tail`.
Анти-паттерн `cat file | grep x` — правильно `grep x file` (это называют UUOC, useless use of cat).

## 8. less — нормальный просмотр больших файлов

```bash
less /var/log/syslog
less +F /var/log/syslog     # режим "follow", как tail -f (Ctrl+C — выйти из follow)
journalctl | less
```

Горячие клавиши (это надо выучить — экономит часы):

| Клавиша | Действие |
|---------|----------|
| `Space` / `f` | страница вниз |
| `b` | страница вверх |
| `↓` / `↑` или `j` / `k` | строка вниз/вверх |
| `g` | в начало файла |
| `G` | в конец файла ← куда чаще всего надо в логах |
| `/текст` | поиск вперёд |
| `?текст` | поиск назад |
| `n` / `N` | следующее / предыдущее совпадение |
| `-N` | включить номера строк |
| `-S` | не переносить длинные строки |
| `F` | следовать за файлом (live tail) |
| `q` | выход |

`more` — старый и слабый аналог (не умеет листать назад). Мнемоника: *less is more* — `less` мощнее.

## 9. history — история команд

```bash
history                  # вся история с номерами
history 20               # последние 20
!!                       # повторить последнюю команду
sudo !!                  # повторить последнюю ЧЕРЕЗ SUDO ← классика, когда забыл sudo
!123                     # выполнить команду №123 из истории
!ssh                     # последнюю команду, начинавшуюся с ssh
!$                       # последний аргумент предыдущей команды
history -c               # очистить историю текущей сессии
```

**Ctrl+R** — интерактивный поиск по истории. Жми Ctrl+R, печатай кусок команды, Ctrl+R снова — следующее
совпадение, Enter — выполнить, стрелка вправо — отредактировать. **Это главный ускоритель в терминале.**

История лежит в `~/.bash_history`, пишется при выходе из шелла (`HISTSIZE`, `HISTFILESIZE` в `~/.bashrc`).

⚠️ **Безопасность:** пароли и токены, введённые в команде, попадают в историю в открытом виде.
Не делай `mysql -u root -pSuperSecret`. Если случилось — почисти `~/.bash_history` и **смени пароль**.
Команда, начинающаяся с пробела, не попадает в историю (если `HISTCONTROL=ignorespace`).

## 10. cp — копирование

```bash
cp file.txt copy.txt            # файл → файл
cp file.txt /tmp/               # файл → каталог
cp f1 f2 f3 /tmp/               # несколько файлов → каталог
cp -r dir/ /tmp/                # КАТАЛОГ (рекурсивно) — без -r не скопируется
cp -i file.txt copy.txt         # спросить перед перезаписью
cp -n file.txt copy.txt         # не перезаписывать (no-clobber)
cp -v ...                       # verbose, показать что копируется
cp -p file.txt copy.txt         # сохранить права, владельца, времена
cp -a dir/ dir2/                # архивный режим = -dR --preserve=all ← лучший выбор для бэкапа
cp -u src dst                   # копировать только если исходник новее
cp --backup=numbered f1 f2      # сделать резервную копию перед перезаписью
```

⚠️ **Ловушка слеша:**
```bash
cp -r /src/dir  /dst/    # → /dst/dir     (скопирует САМ каталог)
cp -r /src/dir/ /dst/    # → тоже /dst/dir у cp (а вот у rsync разница принципиальна!)
```

⚠️ `cp` **по умолчанию молча перезаписывает**. На сервере перед перезаписью конфига делай:
```bash
sudo cp -a /etc/nginx/nginx.conf /etc/nginx/nginx.conf.bak.$(date +%F_%H%M)
```

## 11. mv — переместить / переименовать

В Linux **переименование = перемещение**, отдельной команды `rename` в базовом наборе нет.

```bash
mv old.txt new.txt              # переименовать
mv file.txt /tmp/               # переместить
mv dir1 dir2                    # переименовать каталог (без -r!)
mv -i src dst                   # спросить перед перезаписью
mv -n src dst                   # не перезаписывать
mv -v src dst                   # показать что делает
mv *.log /var/log/archive/      # переместить по маске
```

Важное отличие от `cp`: если источник и приёмник **на одном разделе**, `mv` просто меняет запись в
каталоге (мгновенно, даже для 100 ГБ). Если на **разных** — это реально копирование + удаление (долго,
может прерваться и оставить мусор).

## 12. mkdir — создать каталог

```bash
mkdir mydir
mkdir dir1 dir2 dir3
mkdir -p a/b/c/d             # создать всю цепочку; НЕ ругается, если уже есть ← используй всегда в скриптах
mkdir -m 750 secure          # сразу с правами
mkdir -pv /opt/app/{bin,etc,log}   # brace expansion: создаст три подкаталога
rmdir emptydir               # удалить ТОЛЬКО пустой каталог (безопасно)
```

`mkdir -p` идемпотентен — запускай сколько угодно раз, результат один. Это ключевое свойство
для скриптов и Ansible.

## 13. rm — удаление (самая опасная команда)

```bash
rm file.txt                  # удалить файл
rm -i file.txt               # с подтверждением
rm -f file.txt               # молча, не ругаться на отсутствующий
rm -r dir/                   # рекурсивно каталог
rm -rf dir/                  # рекурсивно и без вопросов ← ОПАСНО
rm -- -file                  # удалить файл, имя которого начинается с дефиса
```

🔴 **Корзины нет. `rm` = безвозвратно.**

Правила выживания:
1. Перед `rm -rf` **сначала выполни ту же команду с `ls`**:
   ```bash
   ls -d /opt/app/tmp/*        # посмотрел, что попадёт под раздачу
   rm -rf /opt/app/tmp/*       # только теперь удаляй
   ```
2. Никогда не используй переменную без кавычек и проверки:
   ```bash
   rm -rf "$DIR"/*      # если DIR пустая → rm -rf /* → КОНЕЦ СЕРВЕРА
   # правильно:
   [[ -n "${DIR:-}" && -d "$DIR" ]] || { echo "bad DIR" >&2; exit 1; }
   rm -rf -- "${DIR:?DIR is empty}"/*
   ```
3. Осторожно с пробелом: `rm -rf /home /user/tmp` вместо `/home/user/tmp` — удалит `/home`.
4. На проде — снапшот/бэкап до операций удаления. В стенде — `vagrant snapshot save`.

💡 Безопасная альтернатива для интерактивной работы: `trash-cli` (`sudo apt install trash-cli`, затем `trash-put`).

## 14. find — поиск (самая полезная команда темы)

```bash
find <где> <условия> <действие>
```

```bash
find . -name "*.log"              # по имени (регистрозависимо)
find . -iname "*.LOG"             # без учёта регистра
find /etc -type f                 # только файлы   (d — каталоги, l — симлинки)
find / -name "nginx.conf" 2>/dev/null    # спрятать ошибки "Permission denied"

# по размеру
find /var/log -size +100M         # больше 100 МБ
find . -size -1k                  # меньше 1 КБ
find . -empty                     # пустые файлы и каталоги

# по времени
find /var/log -mtime -1           # изменённые за последние 24 часа
find /var/log -mtime +30          # старше 30 дней
find /tmp -mmin -15               # изменённые за последние 15 минут
find . -newer reference.txt       # новее указанного файла

# по владельцу и правам
find /home -user vagrant
find / -perm -4000 2>/dev/null    # SUID-файлы ← базовая проверка безопасности
find /var/www ! -user www-data    # НЕ принадлежащие www-data

# глубина
find . -maxdepth 1 -type f        # только текущий уровень
find . -mindepth 2

# логика
find . -name "*.log" -o -name "*.txt"        # ИЛИ
find . -type f -name "*.log" -size +10M      # И (по умолчанию)
find . -type f ! -name "*.log"               # НЕ

# ДЕЙСТВИЯ
find . -name "*.tmp" -delete                       # удалить найденное
find . -name "*.log" -exec gzip {} \;              # выполнить для каждого ({} = найденный файл)
find . -name "*.log" -exec rm {} +                 # то же, но пачкой — БЫСТРЕЕ
find . -name "*.conf" -exec grep -l "listen" {} \; # найти конфиги со словом listen
find . -type f -print0 | xargs -0 grep "error"     # через xargs, -print0 спасает от пробелов
```

**Реальные однострочники, которые будешь использовать на работе:**

```bash
# Чистка старых логов (классический cron-джоб)
find /var/log/myapp -name "*.log" -mtime +14 -delete

# Кто съел диск: топ-20 самых больших файлов
find / -xdev -type f -printf '%s %p\n' 2>/dev/null | sort -rn | head -20

# Найти файлы, изменённые за последний час (после инцидента — «что поменялось?»)
find /etc -mmin -60 -type f

# Найти все симлинки, ведущие в никуда
find /etc -xtype l
```

`locate` — быстрая альтернатива (ищет по индексной базе), но база обновляется по расписанию (`updatedb`),
поэтому свежие файлы не находит:
```bash
sudo apt install plocate && sudo updatedb && locate nginx.conf
```

## 18. alias — свои сокращения

```bash
alias                            # показать все алиасы
alias ll='ls -lah'               # создать
alias                            # проверить
unalias ll                       # удалить
\ls                              # выполнить ОРИГИНАЛЬНУЮ команду в обход алиаса
type ll                          # узнать, алиас это или нет
```

Алиас живёт только в текущей сессии. Чтобы навсегда — добавь в `~/.bashrc`:

```bash
cat >> ~/.bashrc <<'EOF'
alias ll='ls -lahF'
alias ..='cd ..'
alias ...='cd ../..'
alias grep='grep --color=auto'
alias df='df -h'
alias free='free -h'
alias ports='ss -tulpn'
alias k='kubectl'
EOF
source ~/.bashrc     # применить без перезахода
```

⚠️ **Не делай в проде** `alias rm='rm -i'` — ты привыкнешь, что тебя спрашивают, а на чужом сервере
алиаса не будет, и `rm -rf` сработает молча. Учись работать с «голыми» командами.

## 19. exit — выход

```bash
exit          # выйти из shell / закрыть SSH-сессию
exit 0        # выйти с кодом 0 (успех)
exit 1        # выйти с кодом ошибки
Ctrl+D        # то же, что exit (EOF)
logout        # для login-shell
```

**Exit code (код возврата)** — фундамент автоматизации:

```bash
ls /etc; echo $?        # 0  — успех
ls /nope; echo $?       # 2  — ошибка
```

| Код | Значение |
|-----|----------|
| 0 | Успех (и только 0!) |
| 1 | Общая ошибка |
| 2 | Неверное использование команды |
| 126 | Файл найден, но не исполняемый |
| 127 | Команда не найдена |
| 130 | Прервано Ctrl+C (128+2) |
| 137 | Убито `kill -9` (128+9) ← **в Kubernetes это OOMKilled** |

Логические операторы на основе кода возврата:
```bash
mkdir /opt/app && cd /opt/app        # && — выполнить, ТОЛЬКО если предыдущая успешна
command_a || echo "failed"           # || — выполнить, если предыдущая упала
cmd1 ; cmd2                          # ;  — выполнить в любом случае
```
Именно так работают CI-пайплайны: шаг «упал» = ненулевой exit code.

## 🃏 Globbing — шаблоны имён (раскрывает shell, а не команда!)

```bash
*          # любое количество любых символов:  *.log
?          # ровно один символ:                file?.txt
[abc]      # один из перечисленных:            file[123].txt
[a-z]      # диапазон
[!a]       # НЕ a
{a,b,c}    # brace expansion: file{1,2,3}.txt → file1.txt file2.txt file3.txt
{1..10}    # диапазон: file{1..10}.txt
```

```bash
ls *.log            # все логи
rm file?.txt        # file1.txt, fileA.txt — но не file10.txt
cp conf{,.bak}      # хитрый трюк: cp conf conf.bak
echo *              # шелл подставит имена файлов — проверь перед опасной командой!
```

⚠️ Раскрытие делает **shell до запуска команды**. Поэтому `find . -name *.log` без кавычек сломается,
если в текущем каталоге есть `.log`-файлы. Правильно: `find . -name "*.log"`.
А `*` **не включает скрытые файлы** — `rm *` не удалит `.env`.

## 💼 Как это в DevOps

- 95% работы с сервером — это SSH + команды из этой темы. Скорость печати и Ctrl+R = твоя производительность.
- `find` + `-exec` — основа скриптов очистки, аудита и миграций.
- Exit codes — ядро CI/CD: Jenkins/GitLab считают шаг упавшим по ненулевому коду.
- `less +F` и `ls -lrt /var/log` — первые команды при инциденте.
- Все эти команды работают внутри контейнера (`docker exec -it app bash`) — только там часто нет `less`,
  `man` и даже `ls -l --color`. Поэтому важно знать минимум, который есть везде.

## 🧠 Что запомнить

1. Shell ищет команду так: **alias → функция → builtin → $PATH**. `type -a cmd` покажет что есть что.
2. `ls -lrt` в `/var/log` — первое движение при разборе инцидента.
3. `find` — это `find ГДЕ УСЛОВИЕ ДЕЙСТВИЕ`. Условия можно комбинировать, `-exec … +` быстрее `\;`.
4. `rm` необратим. Сначала `ls`, потом `rm`. Переменные — только в кавычках и с проверкой.
5. Exit code `0` = успех. На этом стоит весь CI/CD и `&&`/`||`.
6. Globbing раскрывает **shell**, а не команда. Отсюда кавычки в `find -name "*.log"`.
7. Ctrl+R и Tab — не «фишки», а базовый навык.

### Блок A. Теория

**A1.** Чем терминал отличается от shell? Приведи по примеру каждого.

<details><summary>Ответ</summary>

Терминал — это программа/устройство ввода-вывода (GNOME Terminal, iTerm, SSH-сессия, tty1).
Shell — интерпретатор команд, работающий внутри терминала (bash, zsh, sh). Терминал показывает текст,
shell его исполняет.

</details>

**A2.** В каком порядке bash ищет команду, когда ты жмёшь Enter? Какой командой это проверить?

<details><summary>Ответ</summary>

alias → shell-функция → builtin → исполняемый файл из `$PATH`. Проверка: `type -a имя`.

</details>

**A3.** Что выведет `echo $PATH` и почему порядок каталогов в нём важен с точки зрения безопасности?

<details><summary>Ответ</summary>

Список каталогов через `:`, просматривается **слева направо**, первый найденный побеждает.
Опасность: если в начало `$PATH` попадёт `.` (текущий каталог) или каталог, доступный на запись всем,
злоумышленник подложит свой `ls` и он выполнится вместо системного.

</details>

**A4.** Назови три времени файла (atime/mtime/ctime). Что изменится у каждого, если выполнить `chmod 644 file`?

<details><summary>Ответ</summary>

atime — время последнего чтения; mtime — время изменения содержимого; ctime — время изменения
**метаданных** (права, владелец, число ссылок) или содержимого. `chmod 644 file` меняет **только ctime**.

</details>

**A5.** Почему в Linux расширение файла не определяет его тип? Какой командой узнать реальный тип?

<details><summary>Ответ</summary>

Расширение — просто часть имени, ядру оно безразлично; тип определяется по содержимому
(magic bytes) и по правам на исполнение. Команда: `file`.

</details>

**A6.** Чем `rmdir` безопаснее `rm -r`?

<details><summary>Ответ</summary>

`rmdir` удаляет только **пустой** каталог: если внутри что-то есть — ошибка. Это защита от
случайного сноса содержимого.

</details>

**A7.** Что такое exit code? Какие коды означают «команда не найдена» и «процесс убит по -9»?

<details><summary>Ответ</summary>

Exit code — число 0-255, которое процесс возвращает при завершении; 0 = успех, всё остальное —
ошибка. `127` — команда не найдена, `137` (128+9) — процесс убит SIGKILL (в k8s обычно OOMKilled).

</details>

**A8.** Почему `find . -name *.log` может работать неправильно, а `find . -name "*.log"` — всегда правильно?

<details><summary>Ответ</summary>

Без кавычек `*` раскрывает **shell** ещё до запуска `find`: если в текущем каталоге есть
`a.log` и `b.log`, команда превратится в `find . -name a.log b.log` → ошибка. Кавычки передают
шаблон самому `find`.

</details>

**A9.** Чем отличается `cp -a` от простого `cp -r`?

<details><summary>Ответ</summary>

`cp -a` = `-dR --preserve=all`: рекурсивно, сохраняет права, владельца, временные метки,
и **не разыменовывает симлинки** (копирует их как ссылки). Обычный `-r` копирует содержимое, но
атрибуты и время теряются, симлинки могут превратиться в файлы.

</details>

**A10.** Почему `mv` большого файла внутри одного раздела мгновенный, а между разделами — долгий?

<details><summary>Ответ</summary>

В пределах одного раздела `mv` — это `rename()`: меняется только запись в каталоге, данные
не двигаются. Между разделами данные нужно физически скопировать на другую ФС, а потом удалить оригинал.

</details>

**B15.** В чём разница между этими тремя строками?
```bash

```

`&&` — выполнить вторую, только если первая вернула 0. `||` — только если первая вернула ненулевой код.
`;` — выполнить обе последовательно независимо от результата.

</details>

**B16.** Что произойдёт и почему это опасно?
```bash

```

<details><summary>Ответ</summary>

`"$DIR"/*` раскроется в `/*` — команда станет `rm -rf /*`, то есть удалением всей системы.
Защита: `set -u`, проверка `[[ -d "$DIR" ]]`, и `"${DIR:?DIR is empty}"` — bash прервёт выполнение,
если переменная пуста.

</details>

**C10. Скрипт-чистильщик.** Напиши `/vagrant/cleanup.sh`, который:
- принимает каталог первым аргументом и число дней вторым;
- **проверяет**, что каталог задан и существует (иначе выходит с кодом 1 и сообщением в stderr);
- выводит список файлов старше N дней;
- спрашивает подтверждение и удаляет их.
*Критерий:* при запуске без аргументов ничего не удаляет и возвращает `exit 1`.

<details><summary>Ответ</summary>

```bash
#!/usr/bin/env bash
set -euo pipefail

DIR="${1:-}"
DAYS="${2:-30}"

if [[ -z "$DIR" || ! -d "$DIR" ]]; then
  echo "usage: $0 <dir> [days]" >&2
  exit 1
fi

echo "Файлы старше $DAYS дней в $DIR:"
mapfile -t FILES < <(find "$DIR" -type f -mtime +"$DAYS")

if (( ${#FILES[@]} == 0 )); then
  echo "нечего удалять"; exit 0
fi

printf '%s\n' "${FILES[@]}"
read -rp "Удалить ${#FILES[@]} файл(ов)? [y/N] " ans
[[ "$ans" == "y" ]] || { echo "отменено"; exit 0; }

printf '%s\0' "${FILES[@]}" | xargs -0 rm -f --
echo "готово"
```

</details>

### Блок D. Инциденты

**D1.** Ты выполнил на сервере `cd /var/log` и `ls` — терминал завис на минуту и вывалил тысячи строк.
Что сделал не так и как надо было?

<details><summary>Ответ</summary>

Сделал `ls` в каталоге с огромным количеством файлов (или `cat` большого лога).
Надо было: `ls | head`, `ls -lrt | tail`, `ls -U | head` (без сортировки — быстрее),
а для просмотра лога — `less` / `tail -n 100`.

</details>

**D2.** Скрипт, написанный на ноутбуке (Windows), на сервере падает с
`/bin/bash^M: bad interpreter: No such file or directory`. Диагноз и лечение?

<details><summary>Ответ</summary>

У файла виндовые окончания строк CRLF: shebang читается как `/bin/bash\r`.
Диагноз: `file script.sh` (покажет `CRLF line terminators`) или `cat -A script.sh` (`^M$`).
Лечение: `dos2unix script.sh` либо `sed -i 's/\r$//' script.sh`. Профилактика — `.gitattributes` с `* text=auto eol=lf`.

</details>

**D3.** Джун выполнил на проде:
```bash
cd /opt/app/releases
rm -rf $OLD_RELEASE/
```
Переменная `OLD_RELEASE` оказалась пустой. Что произошло? Как переписать команду так,
чтобы этого не случилось?

<details><summary>Ответ</summary>

Команда превратилась в `rm -rf /` относительно текущего каталога — то есть `rm -rf` по маске
`/` от `/opt/app/releases`, фактически удалив содержимое каталога релизов (а при абсолютном пути —
и системы). Правильно:
```bash
: "${OLD_RELEASE:?OLD_RELEASE is not set}"
[[ -d "/opt/app/releases/$OLD_RELEASE" ]] || exit 1
rm -rf -- "/opt/app/releases/$OLD_RELEASE"
```

</details>

**D4.** Коллега жалуется: «поставил утилиту `mytool`, а она не запускается — `command not found`,
хотя файл лежит в `/opt/mytool/bin/mytool`». Три возможные причины и как проверить каждую.

<details><summary>Ответ</summary>

(1) Каталога нет в `$PATH` → `echo $PATH`, решение — симлинк в `/usr/local/bin` или добавить путь.
(2) Нет бита исполнения → `ls -l /opt/mytool/bin/mytool`, лечится `chmod +x`.
(3) Бинарник не той архитектуры или не хватает библиотек/интерпретатора → `file` и `ldd` покажут
(`command not found` бывает и когда отсутствует интерпретатор из shebang).

</details>

**D5.** `df -h` показывает, что `/` заполнен на 100%. Нужно за 5 минут найти виновника.
Напиши последовательность команд.

<details><summary>Ответ</summary>

```bash
df -h                                   # какой раздел забит
df -i                                   # не кончились ли inode (частая причина!)
du -xh --max-depth=1 / 2>/dev/null | sort -rh | head
du -xh --max-depth=1 /var | sort -rh | head
find / -xdev -type f -size +500M -printf '%s %p\n' 2>/dev/null | sort -rn | head
lsof +L1 2>/dev/null | head            # удалённые, но открытые файлы держат место
```

</details>

### Блок E. Вопросы с собеседования

**1.** Как найти все файлы больше 100 МБ, изменённые за последнюю неделю?

<details><summary>Ответ</summary>

`find / -type f -size +100M -mtime -7 2>/dev/null`

</details>

**2.** Чем `find -exec {} \;` отличается от `find -exec {} +`?

<details><summary>Ответ</summary>

`\;` запускает команду **отдельно для каждого** найденного файла; `+` собирает файлы в пачки и
запускает команду **реже** — значительно быстрее, но команда должна принимать несколько аргументов.

</details>

**3.** Что означает `2>/dev/null` в конце команды `find`?

<details><summary>Ответ</summary>

Перенаправляет **stderr** (файловый дескриптор 2) в «никуда» — прячет сообщения `Permission denied`,
оставляя только результаты.

</details>

**4.** Как безопасно удалить файлы по маске, не рискуя снести лишнее?

<details><summary>Ответ</summary>

Сначала выполнить ту же команду с `ls`/`find -print`, убедиться в списке, потом `rm`.
Плюс использовать `--` и кавычки, а в скриптах — проверку переменных.

</details>

**5.** Что делает `!!` и `!$`?

<details><summary>Ответ</summary>

`!!` — повторить предыдущую команду целиком; `!$` — подставить последний аргумент предыдущей команды.

</details>

**6.** Как посмотреть последние 100 строк большого лога и следить за новыми?

<details><summary>Ответ</summary>

`tail -n 100 -f /var/log/syslog` или `less +F`.

</details>

**7.** В какой секции `man` искать описание формата `/etc/fstab`?

<details><summary>Ответ</summary>

Секция **5**: `man 5 fstab`.

</details>

**8.** Почему `rm *` не удалит файл `.env`?

<details><summary>Ответ</summary>

Глоб `*` по умолчанию **не совпадает с именами, начинающимися с точки** — скрытые файлы не попадают
в раскрытие (это поведение шелла, включается опцией `dotglob`).

</details>
